# 履歴検索の点検と計測（2026-10-28）

履歴の読み込みを一本化し、metafy を読み込んだバッファ内で復元するようにした。不正な UTF-8 の行を別のコマンドへ変換して返す問題と、部分一致の位置をバイト数で比較する問題も修正した。

## 点検内容

開始時の `main` は `origin/main` と一致し、未コミット変更はなかった。`depup --install --include-pinned` で `serde_json` を1.0.151から1.0.154、`sha2` を0.11.0から0.11.1へ更新し、推移依存とライセンス通知も更新した。メジャー更新はない。更新不要・公開直後などの16件は更新対象外になった。

Rust全42ファイルをASTで分析し、入力境界と未参照シンボルを確認した。長い `highlight_buffer` と `last_word` は状態共有が多く、分割の効果を裏付けられないため見送った。

履歴検索は、64 KiB 超なら全体読み込み、以下なら末尾読み込みという分岐だった。どちらも全体を読むため、使われないチャンク境界処理を削除した。行ごとに UTF-8 を検証し、元から U+FFFD を含む正常な行は保持する。複数行の断片と追記途中の最終行は除外する。

順位付けでは前方一致で落ちる行のハッシュ計算を省き、登録済み候補の参照と追加には `HashMap::entry` を使う。単純なバイト走査では日本語のケースが約15%遅くなったため採用せず、すでに推移依存にある `memchr` 2.8.3を直接依存にして改行と Meta バイトを探す。曖昧照合自体の変更より、読み込みと走査の改善を優先した。

## 測定条件と結果

macOS 27.0.1 / Apple M2、Rust 1.99.0のリリースビルドで比較した。基準ソースは `55adbe6`、依存パッケージの版は更新後にそろえた。同じマシンでは別のビルドも動いていたため、負荷のない環境の絶対値ではない。

[`bench_history.py`](../../scripts/bench_history.py)で各版を3回ウォームアップし、交互に31回ずつ起動した。CLI起動から順位付けまでを含む。10万件の合成履歴は1万種類の行を10回ずつ含む。設定類は一時ディレクトリに分離し、全ケースで出力が一致した。

| ケース | 変更前の中央値 (ms) | 変更後の中央値 (ms) | 短縮率 |
|---|---:|---:|---:|
| 1,000件・前方一致 | 10.420 | 10.274 | 1.4% |
| 10万件・前方一致 | 43.693 | 29.800 | 31.8% |
| 10万件・前方一致なし | 41.037 | 24.983 | 39.1% |
| 10万件・部分一致 | 46.606 | 30.868 | 33.8% |
| 10万件・曖昧一致 | 40.591 | 28.816 | 29.0% |
| 10万件・曖昧一致なし | 39.631 | 29.644 | 25.2% |
| 10万件・日本語の曖昧一致 | 27.066 | 24.711 | 8.7% |

1,000件の差はばらつきより小さく、速度は同等と判断した。通常のディレクトリ別履歴は最大1,000件なので、大きいケースは明示的な `--history-file` 向けの検証になる。

300万行・156 MBの同じ履歴も、両版を交互に3回測った。`/usr/bin/time -l` の最大 RSS の中央値は474,464,256から162,381,824バイトへ65.8%減った。全計測値、標準偏差、入力、コマンド、バイナリと出力のハッシュは[測定データ](history-2026-10-28.json)に保存した。再実行方法は[開発手順](../development.ja.md#履歴検索の計測)を参照。

## 検証

修正前に不正 UTF-8 と日本語の部分一致順位の回帰テストが失敗し、修正後に成功することを確認した。不正な継続行を候補やタスク利用回数に含めないケースと、曖昧一致を文字数で比較するケースも追加した。

`make ci` は797件のテスト、format、clippy、ライセンス確認を通過した。`make dist` も成功した。`astro-sight impact` に未対応の影響はなく、公開 API の変更もない。Python は3.15で実行し、3.7互換の構文も検査した。Linuxでの実行とPython 3.7での実行は手元では未検証。
