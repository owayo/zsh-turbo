# 設定

[README に戻る](../README.ja.md)

設定ファイル: `XDG_CONFIG_HOME` が空でない場合は `${XDG_CONFIG_HOME}/zsh-turbo/config.toml`、未設定または空の場合は `~/.config/zsh-turbo/config.toml`

設定の保存はアトミックに置換します。並行保存では排他的に作成した別々の一時ファイルを使うため、書き込み途中のデータを別の保存処理が上書きしません。

`zsh-turbo configure` で以下のすべての設定を編集できます。設定ファイルを直接編集しても構いません。TUI は読み込んだ設定を編集し、`S` で同じファイルへ保存します。

| タブ | 設定内容 |
| --- | --- |
| Prompt | スタイル、フォントレベル、Transient、ホーム記号、省略する長さ・記号、IP インターフェース（空欄で自動）、コマンド入力位置 |
| Segments | 組込み・カスタムセグメントの左右への配置と順序 |
| Git | ステータス、ahead/behind、stash の表示 |
| Suggest | 検索戦略、ハイライト色、補完候補数、キーの動作、タスクの利用記録 |
| Style | primary / success / error / muted の色、Rainbow の配色 |
| Custom | カスタムセグメントの追加・削除、名前、コマンド、アイコン、前景色、背景色、表示条件 |
| Shell | 補完ディレクトリ、端末連携、表示言語（`auto` / `en` / `ja`）、端末フォント設定 |
| 補完 | CLI の登録・有効化・無効化・削除・再構築 |

`Tab` / `Shift+Tab` でタブを切り替え、上下キーで項目を選びます。`Enter` で編集・切替、左右キーで選択肢や数値を変更します。数値も `Enter` で直接入力できます。編集時は左右キー・`Home`・`End` でカーソルを移動し、`Enter` で確定、`Esc` で取り消します。

**Shell → 表示言語** の既定値は `auto` です。明示的なロケールに従い、`C.UTF-8` またはロケール未設定の場合はローカルのタイムゾーンを参照します。`Asia/Tokyo` と `Japan` は日本語です。「English」または「日本語」を選ぶと固定できます。設定値は `[ui] language = "auto"` / `"en"` / `"ja"` です。**Shell → 端末フォント設定** は TUI を終了して `zsh-turbo font` を起動します。未保存の変更があれば先に保存してください。Ghostty と cmux ではフォントとリガチャを設定し、標準ターミナルと iTerm2 ではプロファイルでの設定手順を表示します。

Style の 4 色、Suggest のハイライト色、Custom の前景色・背景色には色見本が付きます。`Enter` で 256 色パレットを開き、矢印キーまたは `h/j/k/l` で選択、`Enter` で確定、`Esc` で取り消します。`e` で直接入力に切り替えると、色名（`blue` など）、`0`〜`255`、`#RRGGBB` を指定できます。サジェストでは `fg=8,bg=0,bold` などの指定も使え、パレット操作は前景色だけを変更します。

Primary はディレクトリの文字色（Classic の左側では背景色）、Muted は時刻・実行時間の文字色、Success / Error は成功・失敗時のプロンプト記号の色です。カスタム背景色は Classic の左側で使います。Rainbow の左側は個別指定、選択したパレットの順に色が決まり、右側は各セグメントの文字色を使います。

Custom タブでは `n` で追加、左右キーで対象を切り替え、Backspace（⌫）を 2 回押して定義と配置を削除します。名前変更は左右の配置にも反映します。コマンド内の改行は `Alt+Enter` で入力できます。作成したセグメントは Segments タブの Available で選び、`L` で左側、`R` で右側へ追加します。配置済みの項目にも `L` / `R` を使い、左右両方へ表示できます。Backspace で配置解除、`u` / `d` で順序を変更します。プレビューはサンプル表示で、カスタムコマンドは実行しません。

保存後、スタイルやセグメントは次のプロンプト描画で反映します。Transient、サジェスト、Shell の設定を確実に反映するには新しい zsh セッションを開いてください。初期化前に指定した `ZSH_TURBO_*` の設定変数は TOML より優先します。`prompt.ip_interface` も `ZSH_TURBO_IP_INTERFACE` があればそちらを優先します。

`suggest.max_suggestions` は `Ctrl+R` の履歴メニューと `zsh-turbo complete` の最大件数と、入力中に表示する一覧（タスク・サブコマンド・ファイル）の行数です（既定10、`0` で候補なし、`complete` は CLI の `--max` で上書き）。インラインサジェストは上位の前方一致候補を1件、薄い色で表示します。履歴メニューは入力全体を曖昧検索し、前方一致・部分一致・曖昧一致の順、同程度なら使用頻度・新しさの順で選びます。上下キー・Tab で選択し、Enter で入力欄へ戻し、もう一度 Enter で実行します。Esc / Ctrl+C は元の入力を復元します。通常の Tab 補完は維持します。`suggest` は設定の検索戦略を使い、`complete` は既定で前方一致です。どちらも `--strategy prefix|substring|fuzzy` で指定できます。制御文字を含む履歴は表示候補にしません。更新後は `exec zsh` で新しいシェル連携を読み込んでください。

「配色 → Rainbow の配色」は左右キーまたは Enter で選択できます。配色は `default`（標準）、`blue`（青系）、`green`（緑系）、`blue_green`（青緑系）、`purple`（紫系）、`cyan`（シアン系）、`pink`（ピンク系）、`red`（赤系）、`orange`（オレンジ系）、`ocean`（オーシャン）、`forest`（フォレスト）、`sunset`（サンセット）、`pastel`（パステル）、`grayscale`（モノクロ）の14種類です。それぞれ6組の文字色・背景色を順番に使います。隣接するブロックの色相・明暗と、背景に対する文字の読みやすさを調整しています。標準は濃い青・黄・緑・明るい紫・濃い赤・水色の順です。未知の配色名も標準として扱います。

「配色 → Rainbow のブロック」で左右キーを使って左側に配置したブロックを選び、「ブロックの文字色」「ブロックの背景色」を Enter で編集します。色選択画面の上部には、配置済みの全ブロックを実際のプロンプトと同じ並び・配色・区切りで表示します。矢印で色を選んでいる間も、RGB を直接入力している間も、確定前の値をプレビューに反映します。横幅に収まらないブロックは折り返して表示します。Enter で設定に反映し、Esc で取り消すと元の配色に戻ります。見本には文字色と背景色の組み合わせも表示します。表示条件を満たしていないブロックやカスタムブロックも選択できます。個別色はブロック名に紐づくため、並べ替えや一時的な非表示でも別のブロックへ移りません。配色セットを変えても保持されます。「このブロックの個別色を解除」で両方をセットの色へ戻し、`e` による直接入力で空欄にすると片方だけ戻せます。適用対象は Rainbow の左側です。終了コードなどの表示内容と、成功・失敗を示す入力記号の色は維持します。カスタムブロックの改名にも個別色が追従します。

「プロンプト → プロンプト間の空行」で、Enter 後に表示するプロンプトの前へ入れる空行数を0〜10行で指定できます。左右キーで増減し、Enter で数値を直接入力できます。既定は0行です。項目を選択している間は、2つのプロンプトと間の空行をプレビューに表示します。設定キーは `prompt.blank_lines` で、コマンド入力位置とは独立しています。全スタイルに適用され、右プロンプトには空行を追加しません。設定ファイルに10を超える値があっても表示は10行までです。保存後の次のプロンプトから反映され、シェル起動直後と画面消去後にも同じ空行を入れます。過去のプロンプトを簡略化する場合にも間隔を保持します（この版へ更新後、起動済みのシェルには `exec zsh` で新しい連携スクリプトを読み込んでください）。

「プロンプト → コマンド入力位置」で「同じ行」「次の行」を切り替えます。全4スタイルに適用され、`prompt.newline = true` が従来どおりの2行表示、`false` が左側の情報に続けて入力する表示です。右プロンプトは入力行に表示され、過去のプロンプトの簡略表示（transient）は従来どおりです。配色と入力位置は保存後の次のプロンプトから反映されます。
blank_lines = 0         # 前の出力・プロンプトとの空行数（0〜10）

通常画面では `Esc` で終了します。未保存の変更があれば確認を表示し、もう一度 `Esc` で破棄して終了、ほかのキーで画面に戻ります。編集・色選択中の `Esc` は取消です。`q` では終了しません。

```toml
[prompt]
newline = true          # false: 同じ行から入力
prompt_style = "classic"  # lean, classic, rainbow, pure
font_level = "nerd"       # nerd, powerline, unicode, ascii
left_segments = ["os_icon", "dir", "git", "virtualenv"]
right_segments = ["duration", "status", "time"]
transient = true
ip_interface = ""        # 空なら自動、例: en0 / eth0

[prompt.dir]
truncation_length = 3
truncation_symbol = "…"
home_symbol = "~"

[prompt.git]
show_ahead_behind = true
show_stash = true
show_status = true

[suggest]
strategy = "prefix"      # prefix, substring, fuzzy
highlight_color = "fg=8" # zsh region_highlight 形式
max_suggestions = 10
record_task_usage = true # false: タスクの利用を記録しない
record_directory_history = true # false: ディレクトリごとの履歴に追加しない
# 補足: ゴーストテキスト表示は候補が現在の入力の延長 (prefix 一致) の場合のみ。
# substring/fuzzy の途中一致候補は `zsh-turbo suggest`/`complete` では返るが、
# インラインのゴーストテキストとしては表示されない。

# カスタムコマンドセグメント
[[prompt.custom]]
name = "wifi"
command = "networksetup -getairportnetwork en0 | cut -d: -f2 | xargs"
icon = "📶"
fg = "white"
bg = "24"
when = "always"  # または "env:VAR" / "file:path"

[style]
rainbow_palette = "default" # blue, green, ocean, sunset, pastel など
primary_color = "blue"
success_color = "green"
error_color = "red"
muted_color = "bright_black"

[style.rainbow_overrides.os_icon]
fg = "231"
bg = "24"

[style.rainbow_overrides.dir]
fg = "16"
bg = "#f0c674"

[style.rainbow_overrides.git]
fg = "231"
bg = "88"

[shell]
completion_dirs = ""           # 絶対パスを : 区切りで指定（~ や $HOME は展開しない）
term_shell_integration = "auto" # auto, 1（有効）, 0（無効）
```

カスタムセグメントのコマンドはシェル経由で実行され、500ms でタイムアウトします。表示に使うのは stdout のみで、失敗・タイムアウト・stderr のみの出力はスキップされます。macOS と Linux では、タイムアウト時にパイプラインや子プロセスを含む同じプロセスグループを終了します。

## プロジェクトのタスク補完

カレントディレクトリのタスク定義ファイルを読みます。

| コマンド | 定義ファイル |
| --- | --- |
| `make <target>` | `GNUmakefile`・`makefile`・`Makefile`（最初に見つかったもの） |
| `npm run <script>`・`npm run-script <script>`・`pnpm run <script>`・`bun run <script>`・`yarn run <script>` | `package.json` の scripts |
| `uv run <script>` | `pyproject.toml` の `[project.scripts]` |
| `deno task <name>` | `deno.json` または `deno.jsonc` の tasks と `package.json` の scripts |
| `mise run <task>`・`mise r <task>` | `mise.toml` または `.mise.toml` の `[tasks]` と、既定のタスクディレクトリ（`mise-tasks/`・`.mise-tasks/`・`mise/tasks/`・`.mise/tasks/`・`.config/mise/tasks/`）内の実行可能ファイル |
| `just <recipe>` | `justfile`・`Justfile`・`.justfile` のレシピ（非公開レシピは除外） |
| `task <name>`（Go Task） | `Taskfile.yml`・`.yaml` と `.dist` 形式（内部タスクは除外） |

`make`・`just`・`task` はコマンド名を入力した時点で、ターゲットなどを入力欄の下に一覧表示します。ほかのコマンドは、実行に使うサブコマンド（`npm run`・`pnpm run`・`bun run`・`yarn run`・`uv run`・`deno task`・`mise run` または `mise r`）まで入力するとスクリプトやタスクを表示します。コマンド名だけ、または 2 語目を入力している途中では、代わりに `<コマンド> --help` から読み取ったサブコマンドを説明付きで表示し、`-` で始まる語ではオプションを表示します。サブコマンドを選ぶと後ろに空白を付けて入れるため、`run` を選ぶとそのままスクリプトの一覧に進みます。help の出力は一度だけ解析して `$XDG_CACHE_HOME`（既定 `~/.cache`）の `zsh-turbo/subcommands` にキャッシュし、実行ファイルが変わったとき、24 時間後、失敗時は 5 分後に読み直します。上下矢印や Ctrl+R で呼び出した行ではサブコマンドの一覧を出しません。続けて名前を入力すると前方一致で絞り込み、カーソルを行末から移すと一覧を隠します。入力中は「入力候補 → 候補の最大数」の行まで表示し、続きがあれば `…` を表示します。一覧には最大 256 件が入り、下矢印のメニューではすべてを選べます。不正なファイルや大きすぎるファイルは無視し、タスク管理コマンドは実行しません。`zsh-turbo complete --project-only -- "make"` は履歴を含めずにプロジェクトのタスクを一覧表示します。

タスクの一覧では、よく使うタスクを薄い文字で表示し、下矢印で開いたときもそのタスクを選んだ状態にします（選び方は[タスクの利用記録](#タスクの利用記録)）。一覧の並び（名前順）は変えません。入力中の一覧では、薄い候補に対応する項目を、下矢印で開いたメニューの選択と同じシアン色の太字で示します（メニューに入ると行頭に `>` が付きます。メニューに入る前の Enter でこの項目が入るわけではありません）。表示行数や端末の高さに入りきらないときは、この項目が最下行に来る位置まで一覧をずらし、隠れた側に `…` を表示します。下矢印で開くメニューも同じ位置から表示します。薄い候補はタスクだけで（例: `make install`）、以前に付けた引数（`PREFIX=...` など）は付けません。サブコマンドの一覧では、履歴に続きがあればそれを、なければ先頭の項目を薄く表示し、下矢印で開くと薄い候補に対応する項目を選びます（薄い候補が履歴の `uv run pytest -x` なら `run`）。薄い候補は Tab で採用でき、一覧に入る前の Enter は入力中の行（`make` など）をそのまま実行します。「入力候補 → Tab: Default」では通常の zsh 補完を使います。スクリプトは `run`（または `task`）の後で補完し、それ以外の語は既存の補完定義に任せます。

下矢印のメニューでも文字を打てます。打った文字は入力欄に入り、メニューは開いたまま一覧をその場で絞り込みます。日本語などの多バイト文字、貼り付け、Backspace も同じです。一覧の取り直しを待たずに続けて打てます。コマンド名（`make` など）や `npm run` の直後で空白を打っていないときは、区切りの空白を補います。`make` で `install` を選んでいる状態で `i` を打つと、入力欄は `make i` になり、一覧は `i` で始まるターゲットに絞られます。メニューの中では、打った名前と完全に一致する項目も一覧に出して選びます。たとえば `fmt` と `fmt-check` があるとき、メニューで `fmt` まで打つと `fmt` を選び、Enter で `make fmt` になります（`make fmt-check` にはなりません）。メニューに入る前の一覧には、完全に一致する名前は出しません。

完全に一致する項目がなければ、選んでいた項目が一覧に残っている限りその項目を選び続けます。残っていなければ、よく使うタスク（サブコマンドとファイルの一覧では薄い候補に対応する項目）を、それもなければ先頭を選びます。打った直後に Enter を押したときは、新しい一覧が届くのを最大 1 秒待ってから、その一覧で選んでいる項目を入れます。古い一覧の項目は入れず、届かなければ打った文字を残してメニューを閉じます。絞り込んで候補が無くなるとメニューを閉じます。Esc は選択だけを取り消してメニューを閉じ、Ctrl+C はさらに入力を変えるまで一覧も閉じます。いずれの場合も打った文字は残ります（メニューで何も打っていなければ、入力は開いたときのままです）。←→ などそのほかのキーは受け付けず、ビープ音を鳴らします。

### タスクの利用記録

よく使うタスクは、そのディレクトリでの利用回数と、同じディレクトリの履歴での呼び出しの割合から決めます。30 日で重みが半分になる利用回数に、履歴での割合を 3 回分の重みで足し、その値が最も大きいタスクを選びます。どちらもなければ先頭のタスクを選びます。

記録は `${XDG_STATE_HOME:-~/.local/state}/zsh-turbo/task-usage.json` に保存します（`XDG_STATE_HOME` が未設定・空・相対パスなら `~/.local/state` を使います）。ファイルは本人だけが読み書きできる権限（0600）、ディレクトリは 0700 で作ります。保存するのはディレクトリ、コマンド名（`make`・`npm` など）、タスク名、減衰付きの回数、最終利用時刻だけです。実行した行の全文や引数は保存しません。

タスクを実行するコマンドで始まる行を実行したとき、そのディレクトリの定義ファイルにあるタスクだけを記録します。失敗した実行も、実行しようとした回数として数えます。記録する形は次のとおりです。

- `make <ターゲット>`: ターゲットは 1 つだけです。`VAR=値` や `-j8` などのオプションは付けられますが、`-C`・`-f`・`--directory`・`--file`・`--makefile` で別の Makefile を読む行は除きます。
- `just <recipe>`・`task <name>`
- `npm run <script>`・`npm run-script <script>`・`pnpm run <script>`・`bun run <script>`・`yarn run <script>`・`uv run <script>`
- `deno task <name>`・`mise run <task>`・`mise r <task>`

make 以外もタスク名の後ろに引数を続けられます。ただし `--` より前に `-` で始まるオプションがある行は、オプションの位置によらず記録しません。`npm run build --prefix ../other`・`task build -d ../other`・`pnpm run dev --filter web` のように、オプションで実行先や定義ファイルが変わり得るためです。`--` の後ろはタスクへ渡る引数なので、`npm run build -- --watch` は `build` として記録します。

`;`・`&`・`|`・`<`・`>`・括弧・クォート・バックスラッシュを含む行、ターゲットが複数ある行、先頭が空白の行（履歴に残さない慣習に合わせる）は記録しません。ディレクトリとタスクの組は最大 1000 件で、重みが 0.01 未満になった組（1 回だけの利用なら約 200 日後）は捨てます。

記録をやめるには、`zsh-turbo configure` の「入力候補 → タスクの利用を記録」を無効にするか、`config.toml` の `[suggest]` に `record_task_usage = false` を書きます（既定は有効）。無効にすると記録せず、既存の記録も使わないため、そのディレクトリの履歴の傾向だけで選びます。設定ファイルが読めないとき（TOML の構文エラーなど）も記録しません。設定を変えた後はシェルを再起動してください。記録を消すには、記録を無効にし、実行中の記録処理が終わってから `task-usage.json` と `task-usage.lock` を削除します。有効なままだと再び作られます。

### ディレクトリごとの履歴

候補表示と Ctrl+R は、現在のディレクトリで実行したコマンドだけを使います。親・子ディレクトリも別扱いですが、シンボリックリンクで同じ場所を指すパスは共有します。旧共通履歴には実行場所がないため移行せず、記録後のコマンドから候補を選びます。通常の ↑↓ は共通履歴を使い続けます。

保存先は `${XDG_STATE_HOME:-~/.local/state}/zsh-turbo/directory-history/` です（空・相対パスの XDG_STATE_HOME は無視）。ディレクトリのパスをハッシュしたファイル名で、実行行の全文と引数を本人だけが読める権限（0600）で保存します。各ディレクトリの直近 1000 回、最大 1 MiB を保持し、先頭が空白・制御文字や改行を含む行・4096 バイトを超える行は記録しません。設定ファイルが読めないときも記録しません。

「入力候補 → ディレクトリ別の履歴を記録」をオフにするか、`[suggest]` の `record_directory_history = false` で新しい記録を止めます。既存の履歴は候補検索に使い続けます。タスクの利用記録の設定とは独立しています。設定を変えた後はシェルを再起動してください。削除する場合は記録を止め、動作中の記録処理の終了後に `directory-history` ディレクトリを削除します。

公開 CLI の `suggest` / `complete` は既定でこの履歴を使います。`--history-file <path>` を明示すると指定した共通履歴を検索でき、シェル連携は常にディレクトリ別を使います。

## ファイル一覧

`/` を含む語を入力すると、そのディレクトリ内のエントリを入力欄の下に表示します。最後の `/` より後ろの文字列で名前を前方一致で絞り込み、大文字小文字と Unicode の正規化形式の違いは区別しません。IME で入力した文字でも、macOS に多い NFD 形式で保存されたファイル名に一致します。大文字小文字まで一致するものを先に、次にディレクトリ（末尾に `/`）、残りを名前の順に並べます。`.` で始まる名前は、入力した名前が `.` で始まるときだけ表示します。名前がすでに完全に一致している通常ファイルは、入力中の一覧には表示しません。下矢印のメニューでは表示し、打った名前と一致するファイルかディレクトリを選びます（`alpha/` と `alpha.txt` があるときに `alpha` まで打つと `alpha/`）。

`--opt=./path`・`VAR=./path` や、`>./out` のようなリダイレクト先も対象です。コマンド名の位置では実行可能ファイルとディレクトリだけを表示します。`~` と、export された `$HOME`・`${XDG_CONFIG_HOME}` などの変数は検索時に展開し、入力欄の表記はそのまま残します。glob・コマンド置換・`$'...'`・`~user`・export されていない変数を含む語は通常の補完に任せます。

入力中は「入力候補 → 候補の最大数」の行数まで表示し、続きがあれば `…` を表示します（`0` で一覧を出しません）。薄い候補に対応する項目は選択と同じシアン色で示し、入りきらないときはその項目が見える位置まで一覧をずらします。下矢印で、薄い候補に対応する項目（なければ最初の項目）を選び、上下矢印（または Tab / Shift+Tab）で移動します。選択中は最大256件をスクロールして選べます。選択中に打った文字は入力の末尾に続けて入り、タスクの一覧と同じく一覧をその場で絞り込みます（[プロジェクトのタスク補完](#プロジェクトのタスク補完)を参照）。Enter は入力途中の名前を選んだ名前に置き換え、特殊文字をエスケープするか、開いているクォートの中に合わせて入れます。ディレクトリはクォートを開いたまま入れ、その中の一覧に切り替わります。ファイルはクォートを閉じて後ろに空白を入れます。Esc は選択だけを取り消し、Ctrl+C はさらに入力を変えるまで一覧も閉じます。どちらも打った文字は残します。履歴に続きがないときは先頭の項目を薄い文字でも表示し、Tab で採用できます。上下矢印や Ctrl+R で呼び出した行では一覧を出さないため、下矢印で履歴をたどり続けられます。長い名前は端末の幅に合わせて `…` で省略します。ディレクトリの読み取りは 50,000 件または 150 ms で打ち切り、件数を `N+` と表示します。

## CLI 補完の登録

`zsh-turbo configure` の「補完」は登録済みコマンドを一覧表示します。上下キーで選び、Enter でそのコマンドの設定を開きます。`n` で CLI を追加し、名前入力を取り消した場合は下書きを破棄します。詳細画面では Enter で編集、Esc で一覧へ戻ります。Backspace（⌫）または `d` を 2 回押すと削除し、`s` で保存します。`r` で変更のあるキャッシュを再生成、`Shift+R` で保存済みの全登録を強制再生成できます。画面上の再生成項目を選んで Enter でも実行できます。処理中も TUI は操作でき、結果を表示します。登録の追加・無効化・削除後は zsh を再起動してください。登録済み CLI のキャッシュ更新は起動中のシェルにも反映されます。

- **ヘルプ**（既定）: `COMMAND --help` と、そこから見つけたサブコマンドのヘルプを読み、オプション名・サブコマンド・説明・ファイルやパスの引数補完を生成します。一般的な英語のヘルプ形式が対象です。独自形式、動的な候補、親コマンドの共通オプションには公式補完を使ってください。取得は最大4並列、サブコマンド4階層、128ページ、1ページ5秒、全体120秒までです。
- **生成コマンド**: `["tool", "completion", "zsh"]` のように、実行ファイルと引数を JSON 配列で指定します。シェル展開やパイプは使いません。対象 CLI が提供する補完生成コマンドを指定してください。タイムアウトは10秒です。
- **補完ファイル**: 信頼できる zsh の `#compdef` ファイルを指定します。`~/` も使用できます。対象 CLI が未インストールでも登録できます。

補完元は明示的に選びます。別の処理を実行する恐れのある生成コマンドの自動推測は行いません。生成コマンドの出力と補完ファイルは、既存の `fpath` の補完と同様に zsh のコードとして実行されます。

```toml
[[completions]]
command = "tool"
enabled = true
source = "help" # help / generator / file
# generator = ["tool", "completion", "zsh"]
# file = "~/completions/_tool"
watch_files = [] # ラッパーの実体など: ["~/bin/tool-core"]
```

シェル起動時と、その後のプロンプト表示時に、30秒以上間隔を空けてバックグラウンドで更新を確認します。実行ファイルのパス・サイズ・更新時刻などが変わったときだけ SHA-256 を計算し、内容・参照先・登録内容・追加監視ファイルの変更に応じて再生成します。ラッパー、shim、プラグインを使う CLI では「追加で監視するファイル」に実体や設定ファイルを指定してください。ラッパー自体が変わらない更新は、それだけでは検知できません。補完ファイル方式は、補完ファイルに加え、インストール済みなら対象 CLI の実行ファイルも監視します。

保存先は `${XDG_CACHE_HOME:-~/.cache}/zsh-turbo/managed-completions` です。Tab は読み込み済みの関数を使い、zsh の stat モジュールでキャッシュの変更を確認します。キャッシュ管理のためにキー入力や Tab のたびに CLI・help・ハッシュ計算の外部プロセスを起動することはありません。公式補完スクリプト自身が動的な候補を取得するコマンドは実行されることがあります。同じ CLI の生成処理はロックし、構文検証を通ったファイルをアトミックに公開します。失敗時は前の補完を残し、TUI に理由を表示します。生成完了後の次の Tab で反映され、初回生成に失敗した場合は既存の zsh 補完に戻ります。XDG のキャッシュ設定が未指定または空なら `~/.cache` を使います。

`zsh-turbo completion-refresh` ですぐに変更を確認できます。`--force` を付けると、ファイル情報の変化を待たずに再構築します。結果は登録ごとに表示されます。
